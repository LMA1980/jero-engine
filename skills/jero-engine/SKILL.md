# `jero-engine` Compute Runtime, Capability Verification, `jero-diag` & Worker Invariants

## 1. `RecipeRegistry`, Modular Architecture Crates & `SafeTensors` Hydration

- Register compiled architecture recipes across modular crates (`jero-arch-synthetic`, `jero-arch-llama`, `jero-arch-mistral`, `jero-arch-phi3`, `jero-arch-bitnet`, `jero-arch-dory`, `jero-arch-gemma`, `jero-arch-qwen`, `jero-arch-encoder`, `jero-arch-ssm`, `jero-arch-machine`, `jero-arch-vision`, `jero-arch-whisper`) in `RecipeRegistry`, supporting dense/MoE/MLA LLMs (`llama`, `llama4`, `mistral`, `mistral3`, `mixtral`, `phi3`, `phi4`, `bitnet*`, `dory`, `gemma2`, `gemma3`, `gemma3_text`, `gemma4`, `functiongemma`, `qwen2`, `qwen3`, `qwen3moe`, `deepseek2`, `qwen35`, `qwen35moe`), bidirectional encoders/embeddings/rerankers (`modernbert`, `bert`, `nomic-bert`, `bge`, `jina-bert`, `deberta-v3`, `cross-encoder`, `reranker`, `bge-reranker`, `jina-reranker`, `modernbert-reranker`), dense causal text embeddings (`qwen3-embedding`), state-space and hybrid recurrent models (`mamba`, `mamba2`, `rwkv6`, `rwkv7`, `jamba`, `zamba2`, `granitehybrid`, `lfm2`, `lfm2moe`, `granite`), structured machine models (`ttm`, `ft-transformer`, `tabpfn-v2`, `decision-transformer`), vision encoders (`clip`, `siglip`, `VlmMmprojBridge`), and audio ASR (`whisper`).
- Validate `GGUF` (`verify_model_capabilities`) and `SafeTensors` (`verify_safetensors_capabilities`, `verify_container_capabilities`) headers before locking weights, preserving metadata-only verification when `tensors().is_empty()` and enforcing ADR-045 `ArchRecipe::validate_model` whenever populated weight tensors are present.
- `LockedModelWeights` and `ParsedModelContainer` auto-detect container magic (`0x4655_4747` `"GGUF"` vs Hugging Face `SafeTensors`), verify capabilities and memory admission up front, and `mlock` mapped pages zero-copy; `jero-diag` resolves embedded `GGUF` vocabularies or `SafeTensors` sibling `tokenizer.json` / `tokenizer.gguf` / `__metadata__` token tables transparently.
- Zero-KV encoders, rerankers, vision encoders (`nomic-bert`, `bge`, `jina-bert`, `modernbert`, `bert`, `deberta-v3`, `cross-encoder`, `reranker`, `bge-reranker`, `jina-reranker`, `modernbert-reranker`, `qwen3-embedding`, `clip`, `siglip`), and non-autoregressive machine models (`ttm`, `ft-transformer`, `tabpfn-v2`) require zero KV cache allocation (`architecture_requires_kv_cache() == false`), while causal offline-RL `DecisionTransformerRecipe` (`"decision-transformer"`) and audio decoder `WhisperRecipe` (`"whisper"`) allocate causal KV state cleanly (`SingleSlotKvArena::new` / `from_safetensors`).
- `VlmMmprojBridge` and `MmprojLatentBridge` emit Layer-0 continuous `soft_prompt_embeds` consumed ahead of discrete `prompt_tokens` via `ExecutionContext::with_soft_prompt_embeds` into downstream LLMs (`GemmaRecipe`, `Gemma4Recipe`, `Qwen2Recipe`, `Qwen3Recipe`, `LlamaRecipe`).
- Pure linear-time SSM/RWKV architectures (`mamba`, `mamba2`, `rwkv6`, `rwkv7`) allocate O(1) context-invariant dual-bank ping-pong state arenas (`kv_block_count = 0`), while hybrid architectures (`jamba`, `zamba2`, `granitehybrid`, `lfm2`, `lfm2moe`) pair compact KV cache blocks strictly for attention layers with dual-bank recurrent state (`estimate_hybrid_ssm_arena_bytes`).

## 2. Conservative Diagnostic Context Bounds (`n_ctx: 64`), Chat Templates & Stop Termination

- Diagnostic utilities (`jero-diag`) and default integration test harnesses must use conservative context bounds (e.g., `n_ctx: 64`, requiring ~64 KiB KV cache) so tests run cleanly out-of-the-box in unprivileged environments without `InsufficientLockableMemory` (exit code `11`) admission refusal.
- By default, single-prompt diagnostics (`jero-diag`), OpenAI serving (`--serve-openai`), and the 5-pillar open-source evaluation suite (`--eval-suite`) read `tokenizer.chat_template` and `tokenizer.ggml.add_bos_token` to format prompts across ChatML (including `qwen*`, `dory`, `lfm2`, `lfm2moe`), Llama-3, Phi-3/4, Gemma 2/3, Mistral, DeepSeek, and placeholder templates while emitting BOS at most once. Base models with no template fall back to raw prompt text, and `--raw-prompt` bypasses chat-template formatting explicitly.
- `--eval-suite` honors caller-supplied `--n-ctx` and `--max-tokens` without artificial caps, reserving conservative defaults (`n_ctx: 64`, `max_tokens: 16`) only when omitted.
- `SinglePromptEngine`, `WorkerEngine`, and `jero-diag` automatically halt generation upon emitting primary EOS or family stop/EOT tokens (`discover_stop_token_ids`), exclude terminal stop tokens from detokenized output, and report `stop_reason` (`eos_token` / `max_tokens`) in `PassTiming`, JSON benchmark reports, OpenAI `finish_reason`, and worker output slab headers unless `--ignore-eos` is supplied.
- Passing `--model <path.gguf>` always executes real GGUF weights through the hydrated `ArchRecipe` and reports `"execution_mode": "real_gguf"` with `architecture`, `model_filename`, and `quant_summary`. Synthetic `ForwardModel` hardware calibration requires the explicit `--synthetic-matrix` flag (mutually exclusive with `--model`), emitting `"execution_mode": "synthetic_matrix"`.
- Pre-validate compilation locally (`cargo check --target riscv64gc-unknown-linux-gnu --workspace --tests`) before dispatching runs to target hardware.

## 3. Worker Execution (`jero-engine` / Phase 1 Alias `jero-worker`), Phase Scheduling & Repack Residency

- Multi-process worker instances (`jero-engine`, with Phase 1 compatibility alias `jero-worker`) handle decoupled matrix and attention evaluation over Unix domain sockets with shared memory weight arenas.
- Under `ClusterPhasePolicy::Auto` on heterogeneous clusters with `A100` (`VLEN=1024`) and `XSMTVDotII` (`has_ime`), non-guardrail dense, MoE, and BitNet models resolve to `A100Only` (`A100` prefill + `A100` decode); explicit `A100PrefillX100Decode`, `A100PrefillA100Decode`, and `RowSplit` prefill also target `a100_pool`, while guardrails and non-IME / single-cluster hosts stay on `X100Only`.
- `PassTiming`, `RunMetric`, `StatisticsSummary` (`mean`, `median`, `min`, `max`, `stddev`), and `jero-diag` CLI tables report `prefill_tokens_per_sec` (`pp tok/s`, returning `0.0` when `prefill_ns == 0`) alongside `prefill_ms` (`TTFT`) and `decode_tokens_per_sec`.
- `estimate_footprint` / `calculate_footprint` tracks `repack_arena_bytes` (compact nibble `smt.vpack.vv` vs `i8` tiles), bounded `prefill_scratch_bytes`, and `eager_repack_enabled`; `check_memory_admission*` fails closed on `weight_bytes + kv_bytes + prefill_scratch_bytes > budget`, and downgrades (`eager_repack_enabled = false`, `repack_arena_bytes = 0`) when only the optional repack arena exceeds headroom.
- `LockedModelWeights::prepare_repacked_weights` populates the model-scoped `RepackedTensorStore` once in parallel across active `WorkerPool` threads, reuses `ModelView` across repeated prompt runs (`--repeat N`), and clears resident repack allocations and fallback caches cleanly on drop.

## 4. Zero-Allocation Decode, Single-Pool Dedicated Dispatch & Lock-Free `RowSplit`

- `PoolBackend::DedicatedThreads` (`Spin` / `Futex` / `Dual`) spawns strictly `N` fixed OS worker threads without lazy internal Rayon sub-pools; parallel kernels (`gemma`, `weights`, `forward`, `ForwardExec`) dispatch via `WorkerPool::with_current` and `DedicatedThreads` lock-free primitives (`par_chunks_mut`, `try_par_chunks_mut`, `par_for_each_index`, `dispatch_indexed`, `execute_scoped`, `execute_split_scoped`).
- `SinglePromptEngine` retains reusable `logits_buf` and 128-byte aligned `ScratchWorkspace` across forward passes (growing only when capacity increases), attaches `ctx.with_scratch(ws)`, resets via `ctx.reset_scratch()` before each step, and hoists `EnginePhase::Decode` pool entry once around the autoregressive decode loop via `WorkerPool::with_phase_session` while keeping `!Send` caller streaming callbacks (`on_token`) on the host thread.
- Greedy token selection (`sample_greedy_argmax`) dispatches through `jero_kernels_rvv::argmax_f32` (RVV 1.0 `vfredmax.vs` + `vmfeq.vf` + `vfirst.m` on `riscv64`), skipping `NaN` logits and returning `None` on empty or all-`NaN` slices to fail closed.
- Cross-cluster `RowSplit` dispatches directly over disjoint `&mut` output slices via `execute_split_scoped` without per-op `std::thread::scope` spawns or cross-cluster atomics, bypassing splitting below `ROW_SPLIT_MIN_ROWS` (`256`), aligning splits to `4` (GEMV) or `8` (IME) rows, and calibrating decode `RowSplit` weights against sustained multi-core memory bandwidth (`calibrate_bandwidth_split_ratio`).
